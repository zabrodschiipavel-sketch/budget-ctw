# budget-CTW

Рабочий репозиторий по задаче **П4** фонда CPU-Neural Foundations
([постановка](../cpu-neural-foundations/problems/P04-budget-ctw.md), премия $10,000,
тир A — флагманская задача фонда).

Задача: CTW-предсказатель с жёстким бюджетом M узлов, онлайн-вытеснением и
целочисленной арифметикой + граница сожаления относительно лучшего M-листового
дерева.

## Состав подачи по постановке

| Пункт | Что требуется | Доля премии |
|---|---|---|
| (1) | Алгоритм budget-CTW: политика вытеснения + целочисленный KT | (1)+(4) = 30% |
| (2) | Верхняя граница: CTW-компонента + штраф вытеснения | 50% |
| (3) | Нижняя граница: линейный штраф неизбежен при памяти o(T) | 20% |
| (4) | Референс-код ≤1000 строк, эмпирика на 100 МБ против полного CTW | см. (1) |

Пункт (1) отдельной доли не имеет — зачётная единица это связка **(1)+(4)**,
поэтому первая веха работы = алгоритм вместе с кодом и эмпирикой.

## Итог этапа 1: развилка пройдена

**Готовой границы в литературе нет** — правило 4 не срабатывает, идём доказывать сами.
Но разведка изменила расклад по трём пунктам из четырёх:

**Пункт (1) частично занят.** [D2-CTW](https://proceedings.neurips.cc/paper/2017/hash/c366c2c97d47b02b24c3ecade4c40a01-Abstract.html)
(Messias–Whiteson, NeurIPS 2017) — уже существующий CTW с жёстким бюджетом узлов и
вытеснением поддеревьев, при памяти на порядок меньше state-of-the-art. Теории
сожаления в нём нет — это прямо отмечено в рецензии NeurIPS. Значит, наш пункт (1)
нельзя подавать как «первый алгоритм»; защитимые отличия — целочисленная арифметика,
гарантия O(D) на символ и политика вытеснения, выбранная под анализируемость.
D2-CTW становится обязательным базлайном эксперимента.

**Пункт (3) сложнее, чем казалось.** Meron–Feder (2004, DOI: 10.1109/TIT.2004.830749)
даёт сожаление при конечной памяти, но их K — число состояний **всей машины**, а
budget-CTW с M узлами по b бит — это автомат с ≈2^(M·b) состояниями, отчего их
нижняя граница Θ(1/K) вырождается в пустую. Прямого переноса нет. Рабочие маршруты:
нижние границы памяти для задачи экспертов (adversarial, память в битах) либо прямой
counting-аргумент «c·M узлов не различают более O(M) контекстов».

**Пункт (2) выглядит достижимым по эмпирике.** Мост через Space-Saving, намеченный
после волны B, эксперимент отменил (этап 4). Зато на enwik8 штраф вытеснения мал сам
по себе: 12 % полного дерева стоят 0.8 % качества. Плюс из проверки семантики
усечённого дерева получена замкнутая форма локального штрафа — цена отложенного
расщепления узла равна −log₂P_e(лист-фазы).

## Главный результат на сегодня

При 32 МБ памяти budget-CTW на глубине 48 даёт **2.5341 bpc** на enwik8, тогда как
полный CTW на глубине 24 даёт 2.7239 bpc и требует 268 МБ: бюджетный вариант **и
точнее, и в 8.4 раза компактнее**. Полное дерево на глубине 48 потребовало бы 606 ГБ и
невычислимо в принципе, так что бюджет здесь — не экономия, а единственный доступ к
глубоким контекстам.

## Сборка и проверка

```bash
rustc -O --edition 2021 -o bin/ctw.exe src/ctw.rs
rustc -O --edition 2021 -o bin/comparator.exe src/comparator.rs
python tools/validate.py       # 21 сверка с точным эталоном на дробях
python tools/budget_tests.py   # инварианты бюджета и вытеснения
python tools/leak_curve.py data/enwik8   # кривая утечки на 100 МБ
python tools/comparator_check.py          # компаратор vs DP эталон
```

Эталон считает кодовую длину по определению, точной дробью, и покрывает как
равноглубокое дерево, так и усечённое (ленивый порог) — вторая часть проверяет
семантику, в которой узел переходит из листа во внутренний по ходу работы.

Зависимостей нет: ядро — один файл на Rust, эталон — Python из стандартной библиотеки.
Без `--budget` работает полный CTW тем же кодом, поэтому сравнение мерит потерю от
вытеснения, а не разницу двух реализаций.
